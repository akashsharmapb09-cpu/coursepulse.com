# CoursePulse — API Specification (design v0.1)

> **Status: design only.** No endpoint exists yet. Paths and shapes may be refined during implementation, but any change must update this file, `security.md` and the tests together.

## 1. Conventions

- **Base:** `/api/v1` (resource API), `/api/auth/*` (Better Auth, allow-listed), `/api/internal/*` (cron). Same-origin only; no CORS headers.
- **Transport/auth:** HTTPS; session cookie. `GET` is safe and idempotent. Every non-GET requires a valid `Origin`; routes marked **CSRF+** also require header `X-CSRF-Token`.
- **Content:** JSON (`application/json`); exports return files. Strict schemas: unknown keys → 422.
- **Errors:** `application/problem+json` `{ type, title, status, code, requestId, errors?: [{ path, message }] }`.
  `401 unauthenticated` · `403 forbidden` (role) · `404 not_found` (also object not visible to caller) · `409 conflict` (duplicate / state) · `413` · `422 validation_failed` · `429 rate_limited` (+`Retry-After`) · `500 internal` (generic).
- **Pagination:** cursor — `?limit=1..100&cursor=…` → `{ data, nextCursor }`.
- **Roles:** S = student, I = instructor, A = admin. "own" = resource belongs to the caller; "assigned" = caller's `InstructorCourseAssignment`; "eligible" = caller has a `FeedbackEligibility` row.
- **Rate tiers:** see `security.md §10` (auth-login, auth-recovery, submit, search, export, mutate, read).
- **Audit:** every admin mutation, every export, comment moderation, and settings change writes `AuditLog` in the same transaction.
- **Release rule (content analytics/comments):** only for forms in `CLOSED/ARCHIVED` status and only cells with ≥ `min_responses` distinct submissions; otherwise `{ suppressed: true, reason: "insufficient_responses" | "form_not_closed" }` (never the hidden count).

## 2. Authentication (`/api/auth/*`, Better Auth; names depend on the pinned version)

| Method & path                              | Who    | Rules                                                                                                                                                                                                                                 |
| ------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/auth/sign-in/email`             | public | tier auth-login; Turnstile after repeated failures; generic failure body; rejects non-ACTIVE users with the same body                                                                                                                 |
| `POST /api/auth/sign-out`                  | any    | revokes current session                                                                                                                                                                                                               |
| `POST /api/auth/request-password-reset`    | public | tier auth-recovery; **always 202**, same body/timing; Turnstile                                                                                                                                                                       |
| `POST /api/auth/reset-password`            | token  | single-use, 1 h TTL; revokes all sessions; strong-password policy                                                                                                                                                                     |
| `POST /api/auth/change-password`           | any    | **CSRF+**; requires current password; revokes other sessions                                                                                                                                                                          |
| `POST /api/auth/activate` (custom wrapper) | token  | activation link: sets first password, marks email verified; routes minors to `PENDING_GUARDIAN_CONSENT`                                                                                                                               |
| `POST /api/auth/resend-activation`         | public | always 202 and identical body/timing whether or not a pending invitation exists; only acts on accounts still `PENDING_VERIFICATION`; tier auth-recovery                                                                               |
| `GET  /api/auth/get-session`               | any    | no token material in the response                                                                                                                                                                                                     |
| _(everything else, incl. sign-up)_         | —      | **Public self-registration is disabled (D-02):** no sign-up endpoint or page exists; `disableSignUp` is set and a route-manifest test asserts that any sign-up path returns 404. Accounts exist only if an admin created/invited them |

## 7. Analytics, comparison, reports — I (scoped) and A (institution)

Filters (query, all optional, Zod-validated): `academicYear`, `semesterId`, `courseId`, `departmentId`, `instructorId`, `category`, `dateFrom`, `dateTo`, `formId`. For **I**, `instructorId` is forced to the caller; `departmentId` ignored; `dateFrom/dateTo` accepted **only** for count/timeline endpoints (content endpoints return 422 `date_filter_not_allowed`). For **A**, date filters on content are allowed with cell-level k and are audit-logged.

| Method & path                          | Roles           | Returns                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /analytics/summary`               | I, A            | KPIs (courses, responses, avg rating, participation)                                                                                                                                                                                                                                                                                                                   |
| `GET /analytics/course-ratings`        | I, A            | bar-chart series per course/offering (+ `n`)                                                                                                                                                                                                                                                                                                                           |
| `GET /analytics/rating-distribution`   | I, A            | donut series (counts per rating bucket)                                                                                                                                                                                                                                                                                                                                |

| `GET /analytics/category-performance`  | I, A            | radar series by question category (normalized 0–100 + raw scale)                                                                                                                                                                                                                                                                                                       |

| `GET /analytics/response-timeline`     | I, A            | counts per day/week (no content)                                                                                                                                                                                                                                                                                                                                       |

## 8. Search — S, I, A

`GET /search?q=&types=courses,departments,instructors,forms,reports&limit=8` — tier search; `q` 2–64 chars; returns only objects the caller can already see (RLS-scoped), highlight ranges, no comment text, query not logged; `GET /search/suggestions?q=` same rules with `limit ≤ 6`.

## 11. Contract tests (Phase 18)

For every route in this file: (a) unauthenticated → 401; (b) every other role → 403 or 404 as specified; (c) foreign-ID matrix → 404 with empty body data; (d) schema fuzz (unknown keys, oversize, wrong types) → 422/413; (e) cross-origin mutation → 403; (f) rate-limit headers; (g) problem+json shape. The route manifest is generated from the handler definitions so no route can be added without appearing in these tests.
